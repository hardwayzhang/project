# UDP 端口收敛代理需求文档

| 项 | 内容 |
|---|---|
| 文档状态 | Draft |
| 版本 | v0.1 |
| 范围 | 同进程 UDP 端口收敛代理（控制面可改、数据面透传） |

---

## 1. 背景与目标

### 1.1 背景

当前每个房间在进程内持有独立的 UDP 监听端口，客户端需直接与对应房间端口通信。对外需开放大量端口，运维与安全成本高，也不利于统一接入控制。

### 1.2 目标

- **对外收敛**：客户端只与代理对外暴露的 **单个 UDP 端口** 通信。
- **正确上下行转发**：客户端业务数据能到达正确房间；房间回包能回到正确客户端。
- **最小侵入**：
  - 控制协议可扩展（携带 `roomId` 等）。
  - **数据协议不改**：业务 UDP payload 原样转发，不加头、不解析。
- **同进程部署**：代理模块与房间服务运行在同一进程；房间端口可仅绑定本机回环地址。

### 1.3 非目标（首版不做）

- 不修改数据协议包格式。
- 不继续将各房间 UDP 端口暴露到公网。
- 不做跨进程 / 跨机转发。
- 不做“无控制面、纯透明 NAT”方案（缺少 `roomId` 无法稳定 demux）。
- 不做绕过内核的同进程零拷贝投递（可作为后续优化）。

---

## 2. 术语与范围

| 术语 | 定义 |
|---|---|
| 公网端口 `P` | 代理对外唯一 UDP 监听端口 |
| 房间端口 `Rn` | 房间在本机监听的 UDP 端口，建议绑定 `127.0.0.1` |
| 本地端口 `L` | 代理为单个客户端会话分配的本机 UDP 端口，用于与房间通信 |
| 客户端地址 `C` | 客户端源地址 `(client_ip, client_port)` |
| 会话 Session | `C ↔ L ↔ (roomId, Rn)` 的映射关系 |
| 控制协议 | 用于 Bind / Unbind / Heartbeat / Ack 的报文 |
| 数据协议 | 既有业务 UDP payload，代理透传 |

**范围内**：公网收发、控制面会话管理、环回 NAT 上下行转发、房间注册、端口池、超时回收、基础安全与可观测性。

**范围外**：房间内业务逻辑、匹配/大厅、跨机部署、QUIC/TCP 替代方案。

---

## 3. 架构与数据流

### 3.1 总体架构

采用 **公网单端口 + 控制面绑会话 + 数据面环回 NAT**。

房间侧继续使用 `recvfrom` / `sendto`。对房间而言，对端是 `127.0.0.1:L`，而不是真实公网客户端。真实客户端身份由代理会话表维护。

```text
                    ┌─────────────────────────────────────────┐
                    │              同一进程                    │
  Client ──UDP──►  │  Proxy:P ──会话表──► sock L ──UDP──► Room:Rn │
         ◄──UDP──  │         ◄────────── sock L ◄──UDP──         │
                    └─────────────────────────────────────────┘
```

### 3.2 模块职责

| 模块 | 职责 |
|---|---|
| 公网 UDP Socket | 监听 `P`；收发控制包与数据包 |
| 控制面 | 解析 Bind / Unbind / Heartbeat；校验 `roomId`（及可选 token）；创建/销毁会话 |
| 会话表 | 维护 `C ↔ L ↔ (roomId, Rn)` 双向索引 |
| 本地端口池 | 为会话分配独占 `L`；超时或销毁后回收 |
| 房间注册表 | 房间创建/销毁时登记 `roomId → Rn` |
| 数据面 | 命中会话后对 payload **原样**上下行转发 |

### 3.3 上行（Client → Room）

1. 客户端向 `Proxy:P` 发送 **控制 Bind**（含 `roomId`，可选 `token`）。
2. 代理查询房间注册表得到 `Rn`；若房间不存在则返回失败。
3. 为该客户端地址 `C` 分配本地端口 `L`，`bind(127.0.0.1, L)`，写入会话表。
4. 向客户端回 **BindAck**（成功码、可选 `expireMs` 等）。
5. 后续 **数据包**（无代理头）到达 `P`：
   - 用源地址 `C` 查会话；
   - 从 socket `L` 向 `127.0.0.1:Rn` `sendto`，**payload 原样**；
   - 刷新会话 `last_active`。

**未 Bind 的数据包策略（首版定稿）**：静默丢弃，并计数 `drop_unbound_uplink`。不向客户端回数据面错误包，避免与业务协议冲突；客户端应依赖 BindAck / 超时重绑发现失败。

### 3.4 下行（Room → Client）

1. 房间向其对端 `127.0.0.1:L` `sendto` 业务回包。
2. 代理在 `L` 上 `recvfrom` 收到回包。
3. 用 `L` 反查会话得到真实客户端地址 `C`。
4. 从公网 socket `P` 向 `C` `sendto`，**payload 原样**。
5. 刷新会话 `last_active`。

下行身份完全由本地端口 `L` 承担，**不依赖数据协议字段**。

### 3.5 时序

```text
Client                Proxy:P              Session/PortPool           Room:Rn
  |  Bind(roomId)       |                        |                      |
  |-------------------->| 查 roomId→Rn            |                      |
  |                     |----------------------->|                      |
  |                     | 分配 L，建会话           |                      |
  |  BindAck(ok)        |<-----------------------|                      |
  |<--------------------|                        |                      |
  |  Data(payload)      |                        |                      |
  |-------------------->| 查 C→会话               |                      |
  |                     |  L.sendto(Rn, payload) |--------------------->|
  |                     |                        |   reply(payload)     |
  |                     |  L.recv / 反查 C        |<---------------------|
  |  Data(payload)      |                        |                      |
  |<--------------------|                        |                      |
```

## 4. 控制协议与会话模型

### 4.1 控制与数据区分（首版定稿）

**同端口 `P` + 魔数区分**：

- 控制报文：payload 以固定魔数开头（例如 4 字节 `0x55504443` / `"UPDC"`），其后为控制头与字段。
- 数据包：不以该魔数开头；代理在已绑定会话上按数据面透传。

约束：

- 业务数据协议不得使用与控制魔数冲突的包头；若历史协议可能冲突，实现前需做一次样本校验，冲突时改魔数或改为独立控制端口（变更需另开需求）。
- 对外仍只暴露一个 UDP 端口。

### 4.2 控制消息（逻辑字段）

具体二进制布局可在详设中定义；需求层要求至少支持：

| 消息 | 方向 | 必要字段 | 说明 |
|---|---|---|---|
| Bind | C→P | `roomId`；可选 `token` | 建立或刷新会话 |
| BindAck | P→C | `code`；可选 `expireMs` | 绑定结果 |
| Unbind | C→P | （可无额外字段） | 主动销毁会话 |
| Heartbeat | C→P | （可无额外字段） | 刷新活跃时间 |
| HeartbeatAck | P→C | `code`；可选 `expireMs` | 可选 |
| SessionGone | P→C | `code` | 可选：房间销毁或会话被服务端拆除时通知 |

`roomId` 类型与编码（字符串 / uint64 等）由现有房间系统对齐，本文不强制，但需在详设中固定。

### 4.3 会话模型

会话主键：客户端源地址 `C = (client_ip, client_port)`。

会话字段至少包括：

- `client_addr`
- `local_port` / 对应 socket
- `room_id`
- `room_port`
- `created_at` / `last_active`
- `token` 校验结果缓存（若启用）

索引要求：

- 正向：`C → Session`（上行 demux）
- 反向：`L → Session`（下行 demux）
- 按房间：`roomId → Session set`（房间销毁时批量清理）

### 4.4 会话生命周期

| 事件 | 行为 |
|---|---|
| Bind 成功 | 创建会话；若同 `C` 已存在且 `roomId` 相同，则刷新并复用 `L`；若 `roomId` 不同，则先拆旧会话再绑新房间 |
| 上下行数据包 | 刷新 `last_active` |
| Heartbeat | 刷新 `last_active`；会话不存在则回失败码 |
| Unbind | 销毁会话，回收 `L` |
| idle 超时 | 销毁会话，回收 `L`（默认 **60s**，可配置） |
| 房间销毁 | 拆除该 `roomId` 下全部会话；可选下发 `SessionGone` |

### 4.5 客户端 NAT / 源端口变化

UDP 源端口变化视为 **新的 `C`**，旧会话不会自动迁移。客户端必须重新 Bind。旧会话依赖 idle 超时回收。

## 5. 房间注册与端口池

### 5.1 房间注册表

同进程内房间生命周期回调：

- 创建房间：`RegisterRoom(roomId, Rn)`  
  - `Rn` 必须已成功 `bind`（建议 `127.0.0.1:Rn`）。  
  - 重复注册同一 `roomId`：以最新为准或返回错误（实现选一种并在日志中明确；推荐 **拒绝重复注册**）。
- 销毁房间：`UnregisterRoom(roomId)`  
  - 删除注册；批量销毁关联会话；释放相关 `L`。

代理 Bind 时只允许绑定到 **当前已注册** 的 `roomId`。

### 5.2 本地端口池

- 每个活跃会话占用 **一个** 独占本地 UDP 端口 `L`。
- 端口范围可配置（例如 `20000–40000`），避免与系统临时端口及其它服务冲突。
- 分配失败（池耗尽 / bind 失败）时 Bind 返回资源不足错误码。
- 回收后建议 **短冷却时间**（例如 2–5s）再复用，降低晚到包串会话风险。
- 需关注进程 `ulimit -n` 与端口范围容量；容量规划见第 6 节。

### 5.3 房间监听地址

首版要求房间 UDP 可配置为仅监听 `127.0.0.1`，不再对外暴露多端口。公网入口仅为代理端口 `P`。

## 6. 超时、错误码、并发与资源限制

### 6.1 超时与配置项

| 配置项 | 默认建议 | 说明 |
|---|---|---|
| `session_idle_timeout_ms` | 60000 | 无上下行/心跳则回收 |
| `port_reuse_cooldown_ms` | 3000 | `L` 回收后冷却 |
| `max_sessions` | 与端口池大小一致 | 硬上限 |
| `local_port_range` | 可配置 | 决定理论最大会话数 |
| `bind_token_required` | false / true | 是否强制 token |

### 6.2 控制面错误码（逻辑）

| code | 含义 |
|---|---|
| 0 | 成功 |
| 1 | 参数非法（缺 roomId / 报文过短等） |
| 2 | 房间不存在或未注册 |
| 3 | 鉴权失败（token 无效） |
| 4 | 资源不足（端口池耗尽等） |
| 5 | 会话不存在（Heartbeat/Unbind 目标无效） |
| 6 | 内部错误 |

（具体数值可在详设微调，但语义需稳定。）

### 6.3 并发

- 公网收包、各 `L` 收包、房间注册/注销可能并发，会话表与端口池需线程安全（锁分片或单线程事件循环均可，详设选定）。
- 同一 `C` 的 Bind 与数据转发需避免 TOCTOU：Bind 完成前数据按未绑定丢弃。

### 6.4 资源与容量

- 最大并发客户端约等于可用本地端口数。
- 需求验收需能配置并验证：在接近 `max_sessions` 时新 Bind 失败且不影响已有会话转发。

---

## 7. 安全

首版最低要求：

1. **房间存在性校验**：禁止绑到未注册 `roomId`。
2. **可选 token**：Bind 可携带 token；开启后无 token 或校验失败拒绝绑定。token 校验接口由房间/账号系统提供（同进程回调即可）。
3. **房间端口不暴露公网**：默认 `127.0.0.1`。
4. **速率限制（建议）**：对同一 `client_ip` 的 Bind 失败次数做简单限速，缓解扫 roomId / 灌包。
5. **不在数据面插入控制语义**：避免污染业务协议。

首版可不做：完整加密、抗重放、跨机 mTLS（同进程无此需求）。

---

## 8. 可观测性

至少提供以下指标/日志字段：

**指标**

- `sessions_active`
- `ports_in_use` / `ports_available`
- `bind_total` / `bind_fail{reason}`
- `uplink_packets` / `downlink_packets`
- `uplink_bytes` / `downlink_bytes`
- `drop_unbound_uplink`
- `session_expire_total`
- `room_register_total` / `room_unregister_total`

**日志**

- Bind 成功/失败：`client_addr`、`room_id`、`code`、`L`
- 会话超时回收：`client_addr`、`room_id`、`L`
- 房间销毁批量踢会话：`room_id`、`session_count`

注意日志中避免输出完整 token。

## 9. 验收标准

| 编号 | 场景 | 期望 |
|---|---|---|
| A1 | 客户端 Bind 合法 `roomId` | 返回成功；建立会话 |
| A2 | Bind 不存在的 `roomId` | 返回“房间不存在”；无会话 |
| A3 | Bind 后发送业务数据包 | 房间在 `Rn` 收到 **与客户端发送一致** 的 payload；源地址为 `127.0.0.1:L` |
| A4 | 房间向该对端回包 | 客户端在原 UDP 五元组上收到 **一致** payload |
| A5 | 未 Bind 直接发数据 | 包被丢弃；`drop_unbound_uplink` 增加；不破坏其它会话 |
| A6 | 两客户端进不同房间 | 互不串包 |
| A7 | 两客户端进同一房间 | 房间看到两个不同 `L`；回包各自回到正确客户端 |
| A8 | idle 超时 | 会话回收；`L` 经冷却后可复用；超时后客户端需重绑才能继续 |
| A9 | 房间销毁 | 相关会话全部拆除；后续 Bind 该 `roomId` 失败直至重新注册 |
| A10 | 端口池耗尽 | 新 Bind 返回资源不足；已有会话上下行仍正常 |
| A11 | 数据协议兼容 | 抓包确认代理不修改业务 payload 字节 |

---

## 10. 客户端接入约定

1. 只连接代理公网地址与端口 `P`。
2. 发送业务数据前必须先成功 Bind。
3. 建议在会话到期前发送 Heartbeat，或依赖业务包保活。
4. 收到 Bind 失败、或业务长时间无下行时，应重新 Bind。
5. NAT 变化导致源端口改变时，必须重新 Bind。

---

## 11. 后续可选优化（不在首版）

- 同进程零拷贝：代理直接回调房间收包函数，省去环回 UDP，降低延迟与端口占用。
- 独立控制端口或 TCP 控制通道。
- 更细的 QoS、按房间限流、连接迁移（迁移 `C` 而不丢会话）。
- 跨机后端转发。

## 12. 决策记录（已对齐）

| 决策点 | 结论 |
|---|---|
| 控制协议 | 可添加 `roomId`（及 Bind 相关字段） |
| 数据协议 | 不修改，payload 透传 |
| 部署 | 代理与房间同进程 |
| 转发模型 | 每客户端独占本地端口 `L` 的环回 NAT |
| 控制/数据区分 | 同端口 + 魔数 |
| 未绑定数据 | 静默丢弃并计数 |
| 默认 idle 超时 | 60s，可配置 |
